# RAG Agent

[![CI](https://github.com/rmouahid/rag-agent/actions/workflows/ci.yml/badge.svg?branch=dev)](https://github.com/rmouahid/rag-agent/actions/workflows/ci.yml)
[![Python](https://img.shields.io/badge/python-3.11%2B-blue.svg)](pyproject.toml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

**A question-answering agent over your own documents, built from scratch to
run on a CPU: its own vector indexes (IVF, HNSW, product quantization), a
local LLM, and benchmarks against brute force and FAISS on public datasets.**

![Recall@10 against median query latency for each vector index on 100,000 SIFT1M vectors, with FAISS as a reference](docs/benchmarks/sift_recall_latency.png)

*Each curve is one index swept over its search parameter (`nprobe` or
`ef`) on 100,000 SIFT1M vectors, one thread. Solid lines are this
project's numpy indexes, dashed lines FAISS. Generated by
`benchmarks/ann_benchmark.py` ([docs/benchmarks/sift.md](docs/benchmarks/sift.md)).*

## How it works

```mermaid
flowchart LR
    subgraph ingest [Ingestion]
        S[PDF, Markdown,<br/>web page] --> C[Chunker<br/>fixed or sentence]
        C --> D[Deduplication] --> E[Embedder<br/>all-MiniLM-L6-v2]
    end
    E --> V[(Vector store<br/>brute force, IVF,<br/>HNSW, PQ, IVF+PQ)]
    subgraph answer [Answering]
        Q[Question] --> RW[Query rewriting<br/>optional]
        RW --> R[Top-k search]
        R --> RR[Cross-encoder<br/>reranking, optional]
        RR --> F[Relevance filter]
        F --> P[Prompt fitted to<br/>the context window]
        P --> L[Local LLM<br/>llama.cpp, GGUF]
        L --> A[Answer + sources]
        L -. not enough context .-> R
    end
    V --> R
    API[FastAPI / CLI] --> S
    API --> Q
```

- **Vector search from scratch**: exact cosine scan, IVF with its own
  k-means, a multi-layer HNSW graph, product quantization and IVF+PQ, all
  in numpy, with incremental updates.
- **Retrieval pipeline**: query rewriting, cross-encoder reranking, a
  relevance threshold that refuses to answer without supporting context,
  and an agentic loop that searches again when the first context is not
  enough.
- **Local generation**: llama.cpp with a GGUF model, no inference API; the
  prompt is fitted to the model's context window and the answer cites the
  chunks it was given.
- **Service**: FastAPI (`/ask`, `/ask/stream`, `/documents`, `/health`) and
  a CLI sharing the same code.

## Results

All figures come from scripts in `benchmarks/`, on one CPU thread.

**Vector indexes on SIFT1M** (100,000 base vectors, 200 public queries,
recall@10 against the exact top 10):

| Method | Setting | Recall@10 | p50 latency | p95 latency | Memory | Build |
|---|---|---:|---:|---:|---:|---:|
| Brute force (numpy) | exact scan | 1.000 | 88.19 ms | 111.52 ms | 48.8 MB | 0 s |
| IVF (this project) | 316 lists, `nprobe=16` | 0.971 | 1.17 ms | 5.13 ms | 49.9 MB | 21.6 s |
| HNSW (this project) | `M=16`, `ef=32` | 0.963 | 0.42 ms | 0.49 ms | 70.1 MB | 300.7 s |
| HNSW (this project) | `M=16`, `ef=64` | 0.992 | 0.72 ms | 0.85 ms | 70.1 MB | 300.7 s |
| PQ (this project) | 64 bytes per vector | 0.809 | 38.80 ms | 49.49 ms | 6.4 MB | 500.9 s |
| IVF+PQ (this project) | 32 bytes, `nprobe=16` | 0.518 | 0.92 ms | 1.22 ms | 4.4 MB | 257.4 s |
| FAISS `IndexIVFFlat` | 316 lists, `nprobe=16` | 0.962 | 0.09 ms | 0.12 ms | 49.7 MB | 1.3 s |
| FAISS `IndexHNSWFlat` | `M=16`, `ef=128` | 0.990 | 0.12 ms | 0.15 ms | 62.6 MB | 4.0 s |

Every setting of every index is in [docs/benchmarks/sift.md](docs/benchmarks/sift.md).

**Retrieval quality on BEIR SciFact** (5,183 scientific abstracts, 300

**Retrieval on the project's golden dataset** (50 questions with

## Technical choices and limits

**Choices**

- **Indexes written by hand, measured against FAISS.** The point is to
  understand and control every trade-off (recall, latency, memory, build
  time); FAISS is the yardstick, not a dependency.
- **HNSW as the default approximate index.** On both SIFT1M and the
  project's own embeddings it reaches the recall of an exact scan at a
  fraction of its latency; IVF builds much faster and stays useful when the
  corpus changes often.
- **A local LLM through llama.cpp.** No API key, no data leaving the
  machine, CPU-friendly quantized weights
  ([ADR 0001](docs/ADR/0001-local-llm-runtime.md)).
- **No LangChain.** Chunking, prompt fitting, reranking and the agentic
  loop are short, tested modules; each step can be switched on or off and
  evaluated alone.
- **Refuse rather than guess.** Below a relevance threshold the agent says
  the documents do not cover the question, without calling the model; above
  it, the prompt tells the model to answer only from the passages.

**Limits**

- Pure numpy is 6 to 13 times slower per query than FAISS at the same
  recall, and HNSW construction is slow (5 minutes at 100,000 vectors,
  against 4 s for FAISS) because insertion runs in Python.
- Product quantization keeps memory low but loses too much recall on SIFT1M
  to be used alone.
- Answer faithfulness is not published yet: the evaluation harness
  (`rag-agent eval --judge`) exists, but a local judge needs more than one
  CPU.
- The relevance threshold alone refuses none of the 7 unanswerable
  questions of the golden dataset: they use the corpus vocabulary, so their
  passages score above it, and the refusal is left to the model.
- The store lives in process memory and on local disk: one node, no
  sharding, no concurrent writers.

## Quickstart

Requirements: Docker and about 3 GB of disk for the model.

```bash
git clone https://github.com/rmouahid/rag-agent.git && cd rag-agent
curl -L --create-dirs -o models/Llama-3.2-3B-Instruct-Q4_K_M.gguf https://huggingface.co/bartowski/Llama-3.2-3B-Instruct-GGUF/resolve/main/Llama-3.2-3B-Instruct-Q4_K_M.gguf
docker compose up -d   # API and interactive docs on http://127.0.0.1:8000/docs
```

Then upload a document and ask a question:

```bash
curl -F file=@notes.md http://127.0.0.1:8000/documents
curl -s http://127.0.0.1:8000/ask -H 'content-type: application/json' -d '{"question": "What do my notes say about X?"}'
```
